**Следующие действия по найденным причинам**

1. Получить у хостинга аудит операций выключения / включения VM: инициатор, источник команды, причина и задача платформы для 8 сентября и 21 августа. Приложение не может оставаться доступным при выключенной VM.
2. Добавить внешний контроль доступности `/health/ready` и самой VM: он должен работать вне этого сервера. На VM есть Zabbix agent, но его внешние проверки и получателей оповещений из этой проверки установить нельзя; считать их настроенными оснований нет.
3. При доработке выкладки предусмотреть запуск и проверку нового процесса до переключения трафика. Сейчас `systemctl restart` создаёт короткий разрыв; отдельно стоит воспроизвести старое зависание завершения при активных WebSocket-соединениях в тестовой среде.
4. Для дальнейшего разбора 5xx полезны отдельные access logs TaxiGR / Uletay с hostname, request time, upstream status и upstream response time. Текущий общий формат не позволяет восстановить все задержки задним числом.
