# Уведомления об обновлении приложения

Нативное приложение проверяет `GET /v1/app-releases` при запуске и возвращении из фона (не чаще раза в 30 минут; после сетевой ошибки — через минуту). Сравниваются версия и номер **установленной сборки** из Expo Application, а не app.json или версия JS.

Окно появляется один раз на каждую новую опубликованную сборку, когда пользователь авторизован и находится на главном экране или в профиле без активной поездки/предложения водителю. Если поступит заказ, окно закрывается. Закрытие, выход из аккаунта и повторный запуск не повторяют уведомление. В профилях пассажира и водителя остаётся кнопка обновления. Открытие магазина не считается установленным обновлением. Последняя проверенная версия сохраняется для кнопки в профиле без сети; всплывающее окно требует успешной актуальной проверки сервера.

Android читает установщик через локальный модуль `modules/taxigr-install-source`: `com.android.vending` → Google Play, `ru.vk.store` → RuStore. Если Android потерял эту информацию, используется `EXPO_PUBLIC_DISTRIBUTION_STORE`, заданная в профилях eas.json. При локальной сборке тоже задавайте `google-play` или `rustore` **до сборки JS**. Неизвестный источник без метки не направляется в случайный магазин. Магазин открывается явным Android Intent; если приложение магазина отсутствует — его HTTPS-страница. На iOS используется App Store. Веб, Expo Go, debug и internal-сборки не показывают уведомления магазинов.

## Публикация следующей версии

1. Выпустить **новую нативную сборку** с Expo Application и локальным Android-модулем. Старые уже установленные сборки не получают эту возможность от одного изменения сервера.
2. Дождаться фактической публикации новой версии для всех пользователей нужного магазина. Статус «На модерации», Google Play alpha/beta и частичный rollout не подходят для общего уведомления.
3. Записать подтверждённую версию отдельно для каждого магазина:

   ```powershell
   npm run release:available -- rustore 1.0.11 31 --published "--notes=Улучшили приложение и исправили ошибки."
   npm run release:available -- google-play 1.0.11 31 --published "--notes=Улучшили приложение и исправили ошибки."
   ```

   Номера выше — примеры, используйте реальные номера опубликованных сборок. Скрипт не публикует сборку и не проверяет модерацию; он записывает уже подтверждённую доступность в `server/app-releases.json`.
4. Включить обновлённый JSON в обычный коммит и деплой API. Сервер читает его при каждом запросе. Для снятия уведомления у отозванного релиза установить соответствующую запись в `null` и задеплоить.

Для iOS та же команда со значением `app-store` требует `--app-store-id=ЧИСЛОВОЙ_ID_ПРИЛОЖЕНИЯ`. В проекте этот ID ещё не задан; придуманная ссылка не используется.

Исходный реестр содержит `null`: известная сборка 1.0.10 (29) была отправлена на модерацию, а подтверждения общедоступной публикации нет. Номер из app.json никогда автоматически не становится рекламируемым обновлением. Проверки и тесты используют отдельные тестовые данные и не активируют уведомление в продакшене.
