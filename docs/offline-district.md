# Автономная карта Граховского района

В Android/iOS входят данные OpenStreetMap района, шрифты с кириллицей и дорожный граф.
Первый запуск установленной сборки не должен скачивать ни геометрию, ни подписи карты.
Для района выбирается встроенный стиль сразу. При уходе за его границы приложение
может использовать обычную сетевую карту; этот пакет не покрывает всю Россию.

Снимок от 12 ноября 2026: 7 043 объекта, включая 4 475 зданий. Геометрия и граф
занимают 823 381 байт в пакете JS, шрифты — 314 611 байт. Шрифты Android/iOS
распаковываются из встроенных байтов в файлы приложения без Asset.downloadAsync.
Браузер получает встроенные glyph PBF через data URL. Нативная карта читает file URL.
Источник и лицензия записаны в `assets/offline-map/manifest.json`; лицензия шрифта —
`assets/offline-map/OFL-Noto.txt`. Данные карты: © OpenStreetMap contributors, ODbL 1.0.

Обновление данных перед будущим выпуском:

```powershell
npm run map:offline:download
npm run map:offline:build
```

Скачивание выполняется на этапе подготовки, а не на телефонах. Готовые JSON-файлы
версионируются. Генератор отклоняет неполный ответ Overpass. Сырой источник остаётся
в `tmp/offline-district/osm-source.json`; запрос опубликован в скрипте скачивания.

## Поведение при недоступных серверах

- Сохраняются вход существующего пользователя, карта, выбор адресов, локальная
  привязка GPS к известному дому и предварительный маршрут по дорогам района.
- Маршрут учитывает связность по OSM node ID, односторонние улицы и запрещённый
  доступ. Несвязанные участки не соединяются прямой линией. Это предварительный
  маршрут: отсутствуют текущие перекрытия, пробки и обработка turn-restriction relations.
- Черновик содержит адреса, остановки, оплату, будущее время и комментарий. Он
  восстанавливается после перезапуска. Сохранённые чтения ограничены одним аккаунтом,
  семью днями и лимитом объёма; выход очищает их.
- У водителя сохраняется последний известный назначенный заказ. Сохранённые свободные
  предложения не выдаются за текущие. Баннер сообщает, что статусы требуют подключения.
- Чтения из сохранённых ответов разрешаются явно `offlineFallback: true`. Проверки
  создания/принятия/отмены и восстановления неопределённого результата используют
  свежий API. Черновики не отправляются автоматически; цена подтверждается сервером.
- Обмен заказами между телефонами требует рабочего backend и хотя бы одного канала.
  VK/MAX обходят недоступность основного адреса с телефона, но не заменяют выключенный backend.
- Системные push, фотографии чата и первое подтверждение входа полностью офлайн не работают.

## Прямые нативные каналы

Android/iOS игнорируют `EXPO_PUBLIC_*_RELAY_GATEWAY_URL`. Loopback шлюзы разрешены
только веб-стенду. Нативный клиент обращается к `api.vk.ru` и `platform-api2.max.ru`.
Включённый нативный резерв требует собственной корректной конфигурации токена,
ключа канала и фиксированного служебного получателя; экспорт веб-стенда с пустыми
токенами не является настроенной нативной резервной сборкой.

MAX требует Russian Trusted Root CA. `taxigr-max-tls` использует этот встроенный
сертификат только в отдельном HTTPS-клиенте домена `platform-api2.max.ru`. Проверяются
цепочка, срок сертификата и имя хоста. Перенаправления отключены; общесистемное
доверие устройства, другие домены и проверка TLS не изменяются. iOS использует
SecTrust, Android — системный TrustManager плюс дополнительный корень и стандартную
проверку имени хоста OkHttp. Для этого изменения требуется новый нативный бинарный файл.

## Экономия запросов

- Встроенная карта района не запрашивает тайлы или шрифты по сети.
- При наличии местного результата поиск не отправляется на сервер автоматически.
- Пустая форма не опрашивает доступность заказа каждые 30 секунд.
- Один Socket/резервный опрос разделяется поездкой и чатом. В фоне RideProvider
  закрывает подписку. Фоновая геолокация водителя остаётся отдельным механизмом.
- Ошибки Socket не ускоряют резервный опрос; неудачи увеличивают паузу до минуты.
- Проверки отключённых каналов соблюдают cooldown; рабочий канал не проверяется
  дополнительными сообщениями при каждом истечении минуты.
- Неактивный relay worker увеличивает паузу чтения служебного диалога до 4 секунд.
  Ожидание полного health round trip увеличено до 8 секунд, чтобы учитывать эту паузу.

Локальный браузерный стенд и JS-экспорты не подтверждают прохождение доменов через
белый список конкретного оператора и реальную работу GPS/фоновых push на устройстве.
