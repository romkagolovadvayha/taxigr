# Ошибки фронтенда из Telegram — 9 сентября 2026

**Исправления подготовлены локально. На production в рамках этой задачи не выкладывались.**

Присланные сообщения описывают два разных сбоя браузерного приложения. Они могут происходить при работающем API и не означают аварийное завершение серверного процесса.

| Ошибка | Причина и влияние | Изменение |
| --- | --- | --- |
| `J.at is not a function`, версия 1.0.8, `RideProvider`, fatal | При начальном рендере вызывается `destinations.at(-1)`. Chrome 79 и Safari 15.3 не имеют этого метода. Пустой массив тоже вызывает ошибку: метода нет у самого массива | Все вызовы `.at()` в собственном коде `src` заменены обращением по индексу, включая маршруты, чат, навигацию и курсоры списков |
| `Coverage fetch failed … Load failed`, версия 1.0.9, nonfatal | Асинхронный запрос SDK Яндекс Карт к `api-maps.yandex.ru/services/coverage/v2` не загрузился на клиенте. Статус «онлайн» не гарантирует доступность конкретного ресурса. По одному сообщению нельзя установить, был ли причиной провайдер, сеть устройства или прерывание запроса | Активная карта распознаёт именно этот отказ, освобождает экземпляр SDK и предлагает повторную загрузку. Ошибка продолжает передаваться в мониторинг как нефатальный сбой ресурса |

Наличие `.at()` в Safari начиная с 15.4 подтверждено [WebKit](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/), в Chrome начиная с 92 — [V8](https://v8.dev/features/at-method). В текущем исходном коде 1.0.9 проблемные вызовы также оставались, поэтому смена версии с 1.0.8 сама по себе их не устраняла.

Дополнительно заменён `replaceAll()` в подписях маршрута на `replace()` с глобальным регулярным выражением. ESLint запрещает повторное появление вызовов этих методов в `src`, сохраняя возможность использовать обычные поля с именем `at`, например время измерения GPS.

Для Яндекс Карт внесены следующие изменения:

- Карта освобождается, когда её экран теряет фокус. Expo Stack может сохранять предыдущий экран смонтированным после перехода на `/profile` или поиск адреса; теперь скрытая карта не остаётся активной. Само присланное событие не доказывает, что запрос был начат уже после перехода: мог завершиться ранее начатый запрос.
- Сетевой отказ coverage обрабатывается только для точного origin и пути Яндекса. Другие ошибки приложения и других сетевых ресурсов проходят обычную обработку. Глобальный монитор по-прежнему получает событие; координаты из query string не включаются в нормализованный адрес ресурса.
- На экране ошибки появилась кнопка повторной загрузки карты. Повтор создаёт новый экземпляр карты. Успешная инициализация очищает ошибку на экране выбора точки дома.
- Отклонение `ymaps3.ready` теперь отклоняет и обещание загрузчика, вместо необработанного исключения внутри `async onload` и зависшего ожидания.
- Загрузка ограничена 15 секундами. При отказе сбрасывается сохранённое обещание, неудачный script удаляется. Следующая попытка может снова загрузить SDK. Если уже загруженный SDK сам постоянно отклоняет `ready`, его повторное ожидание также вернёт ошибку; может потребоваться обновление страницы.

Работа с готовностью SDK сверена с [документацией подключения Яндекс Карт](https://yandex.ru/maps-api/docs/js-api/common/connection/javascript.html). Внешний сетевой отказ нельзя устранить изменением нашего API; изменения дают пользователю способ восстановить карту и корректно обрабатывают ошибку в приложении.

**Проверки:**

- 33 теста в 9 файлах прошли. В том числе синхронное выполнение операций маршрута при отключённых `Array.prototype.at` и `String.prototype.replaceAll`, сетевой отказ и повтор загрузки SDK, отклонение `ready`, два варианта тайм-аута, одновременные потребители загрузчика, очистка подписки и сохранение мониторинга.
- TypeScript: `tsc --noEmit` — успешно.
- ESLint по `src` и новым тестам — успешно. Отдельно проверено, что правило запрещает вызов `.at()`, но разрешает обычное поле `.at`.
- Expo web export — успешно, 41 статический маршрут. Сборка сохранена отдельно от обычного `dist` в каталоге визуализаций задачи `frontend-errors-web-check`.

Реальные Chrome 79 и Safari 15.3 не запускались; отсутствие конкретных методов воспроизведено в тестах. Сборка проверена с текущими параллельными изменениями интерфейса в общей рабочей папке. Она не является изолированным релизом только этих исправлений. После будущей выкладки уже открытые вкладки со старым JavaScript потребуется обновить.
