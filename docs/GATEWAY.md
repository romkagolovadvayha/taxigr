# Прокси и Telegram-вебхуки

Настройки находятся в **Админка → Настройки сервиса → Прокси и вебхуки Telegram**.
Доступ имеет роль `admin` — супер администратор сервиса. API дополнительно
проверяет актуальную роль в БД, поэтому отозванные права не продолжают действовать
до истечения старой сессии.

Исходящие запросы Telegram Bot API и загрузка аватаров используют HTTPS-прокси
`https://proxy.prostoj.store:443` с отдельными логином и паролем проекта.
Настройки читаются из MySQL при каждом запросе; соединения переиспользуются,
смена прокси применяется без перезапуска. Выключатель явно разрешает прямые
запросы. При ошибке прокси автоматического обхода через прямое соединение нет.

Входящие Telegram-вебхуки передаются через `https://hooks.prostoj.store/relay`.
Подпись — HMAC-SHA256 строки `prostoj-hooks-v1\nPROJECT\nEXACT_TARGET_URL`
с ключом `webhook_secret` как строкой, без декодирования hex. Адрес назначения:
`https://api.taxigr.ru/v1/webhooks/telegram`. Telegram по-прежнему передаёт
`X-Telegram-Bot-Api-Secret-Token`, и приложение проверяет его независимо от шлюза.

После сохранения нажмите **Проверить соединение**, затем **Зарегистрировать вебхук**.
Регистрация сохраняет очередь событий (`drop_pending_updates=false`) и подписывает
бота на `message` и `callback_query`. **Проверить вебхук** сверяет фактический адрес
в Telegram с настройками и показывает число ожидающих событий и дату последней
ошибки. Полные подписанные ссылки интерфейс не получает.

## Первичная настройка

1. Выполните `npm run db:migrate`.
2. Получите собственный проект `taxigr` через `gatewayctl create` у владельца Prostoj.
   Административный токен шлюза приложению не нужен.
3. Заполните поля в админке или один раз импортируйте приватный JSON от `gatewayctl`:

   ```sh
   node scripts/run-server-with-ca.mjs server/scripts/import-gateway-settings.ts /private/taxigr.gateway.json https://api.taxigr.ru
   npm run telegram:webhook:register
   ```

Импорт разрешён для ещё не настроенной записи; повтор с теми же значениями
ничего не меняет. Другие сохранённые настройки импорт не перезаписывает.
Перед активацией релиза деплой проверяет заполненность настроек и связь с Telegram;
после запуска API регистрирует вебхук и сверяет результат. При повторных развёртываниях
значения из БД сохраняются. После смены проекта, ключа, адреса API или выключателя
шлюза повторите регистрацию вебхука. Старый polling удалён.

`TELEGRAM_PROXY_URL` и `TELEGRAM_UPDATE_MODE` больше не используются ни приложением,
ни workflow; удалите старые GitHub Environment secrets/variables после перехода.
Токен бота и проверочный секрет провайдера остаются серверными параметрами
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`.

## Хранение и восстановление

Таблица `gateway_settings` содержит одну запись. Пароль прокси и HMAC-ключ
зашифрованы AES-256-GCM ключом, полученным из серверного `JWT_SECRET` с отдельным
контекстом. Сохраняйте резервную копию БД вместе с исходным серверным ключом.
При смене `JWT_SECRET` сначала перенесите секреты под новый ключ; простая замена
ключа делает существующие значения нечитаемыми. Приватный файл проекта позволяет
восстановить настройки. Секреты отсутствуют в ответах API и журнале аудита;
пустое поле при сохранении оставляет прежний секрет. API принимает `null` для
явного удаления секрета при выключенной соответствующей функции.

Источники протокола: документация проекта Prostoj и
[Telegram Bot API](https://core.telegram.org/bots/api#setwebhook).
