# Исправления маршрутизации — 8 сентября 2026

Исправлены три ошибки из [исходного аудита](2026-09-08-routing-audit.md). Проверка выполнена на локальном API с отдельной базой `taxi_route_audit_20260908`; рабочая база не изменялась.

## Изменения

1. **Приблизительные координаты домов.** Адреса ГАР и ручного ввода явно помечаются как приблизительные. Для заказа к конкретному дому пользователь должен выбрать точку на карте и подтвердить её. До этого API отклоняет такой адрес, включая старые сохранённые адреса с префиксами `gar:` и `manual:`. Существование дома в справочнике больше не означает точность его координат. Выбор населённого пункта как назначения остаётся разрешённым. Индивидуальные координаты всех 4 266 домов в справочник не добавлялись.
2. **Пройденные остановки.** В заказе сохраняется индекс следующей точки. Водитель нажимает «Остановка N пройдена»; карта, подсказка следующего адреса и внешний навигатор переходят к оставшейся части маршрута. API проверяет водителя, статус и порядок остановок; повторный запрос безопасен, а завершение поездки до подтверждения промежуточных остановок блокируется. После перезапроса заказа прогресс сохраняется.
3. **Повторяющиеся точки.** Последовательные дубли одного адреса удаляются до расчёта расстояния и цены. Разные дома с одинаковыми приблизительными координатами не объединяются; возврат A → B → A сохраняется. Нулевые расстояние и время корректно обрабатываются. Попытка заказа A → A возвращает `422 IDENTICAL_ROUTE_POINTS` вместо вымышленных 800 м и 5 минут.

## Установка и границы проверки

- Перед запуском обновлённого сервера требуется [миграция 044](../../server/migrations/044_order_stop_progress.sql), добавляющая `orders.next_destination_index`. В изолированной тестовой БД она уже применена. Сервер и клиент с поддержкой подтверждения остановок нужно обновлять совместно. У существующих заказов индекс начинается с нуля.
- Изменения находятся локально; публикация и миграция рабочей базы не выполнялись.
- Дорожные запросы проверялись через публичный OSRM; этот же адрес указан в GitHub workflow деплоя. Фактическая конфигурация развёрнутого сервера отдельно не проверялась, региональный OSRM из Docker-конфигурации не запускался.
- Полный пассажирский сценарий через авторизованный интерфейс и физические устройства iOS/Android не пройден. Автоматическая проверка разрешений ранее отклонила ввод тестового телефона и отметку согласия на экране входа; этот запрет не обходился. Проверка компонента карты не заменяет полный сценарий заказа.
