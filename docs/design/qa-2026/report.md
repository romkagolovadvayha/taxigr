# Проверка проекта — 9 сентября 2026

Проверены 470 автоматических тестов: 424 модульных, 33 существующих интеграционных сценария API и 13 новых сценариев конкурентной работы. Все завершились успешно после исправлений. Дополнительно проверен интерфейс в пяти независимых браузерных сессиях: три пассажира и два водителя с настоящими запросами API, базой данных и Socket.IO.

## Найдено и исправлено

1. **Повторная отправка одного заказа иногда возвращала `ACTIVE_ORDER_EXISTS`.** Проверка ключа повторного запроса выполнялась до блокировки пассажира и пропускала заказ, созданный параллельным запросом. Теперь проверка повторяется после получения блокировки. 16 одновременных одинаковых запросов возвращают один и тот же заказ, в базе остаётся одна запись.
2. **Независимые заказы могли завершаться ошибкой `ER_LOCK_DEADLOCK`.** Пересекались блокировки диапазонов индексов; при общем устройстве добавлялся конфликт повышения разделяемых блокировок. Для создания и принятия заказа применён `READ COMMITTED`, сохранены явные блокировки пассажира, устройства, телефона, водителя и заказа. Ключи идентичности блокируются в одинаковом порядке с получением исключительной блокировки сразу. Ограничения количества активных заказов сохраняются. Настройка изоляции действует только для следующей транзакции, как описано в [документации MySQL](https://dev.mysql.com/doc/refman/8.0/en/set-transaction.html).
3. **У другого водителя оставался уже занятый заказ.** Добавлено событие `order:unavailable` для назначения, отмены и истечения поиска. Клиент убирает устаревшее предложение и загружает доступные заказы. Назначенная поездка сохраняется; устаревший ответ обновления предложений отбрасывается. Событие содержит только идентификатор заказа и доступно водительским соединениям. Также обновляется состояние при первом подключении сокета, чтобы закрыть промежуток после начальной загрузки.
4. **Отмена запроса Яндекс Карт могла открыть перекрывающее интерфейс окно Expo.** Добавлен узкий обработчик конкретной ошибки отмены coverage-запроса SDK, устанавливаемый до загрузки Expo. Остальные ошибки приложения и реальные ошибки карты не подавляются. Браузерная проверка специально воспроизводит такую отмену и затем продолжает оформление поездки.

Обновлены два устаревших теста графических ресурсов: проверяются используемые приложением WebP-иллюстрации и их размер до 50 КБ; обычные иконки интерфейса больше не обязаны быть растровой картинкой автомобиля.

## Остальная проверка

33 исходных интеграционных теста проверяют авторизацию, роли и доступ, согласия, подтверждение телефона, ограничения аккаунтов, расчёт тарифов и повышение цены поиска, точность адресов, промежуточные остановки, отмены и ограничения частых отмен, наличные и перевод, ожидание и его стоимость, подтверждение оплаты, комиссию и доход, очередь и её продвижение, отказ и повторную выдачу заказа, детское кресло, запрет приёма собственного заказа, геопозицию, чат и фотографии, непрочитанные сообщения, заявки водителей, модерацию автомобиля, административные действия и приоритетную диспетчеризацию.

В пяти браузерных сессиях проверены создание трёх заказов через интерфейс, распределение между двумя водителями, следующий заказ, два чата, перезагрузка всех пяти сессий, отмена текущего заказа и автоматическое продвижение следующего, полный цикл поездки, перешедшей из очереди, и подтверждение получения оплаты. В успешном прогоне не было ошибок JavaScript или ответов API 500.

Дополнительно повторно запущены проверки авторизации на 25 размерах экрана, главной страницы, трёх ролей в светлой и тёмной темах, маршрутов с реальным OSRM и нескольких остановок, восстановления маршрута после сетевой ошибки, геолокации с реальным обратным геокодером Яндекса и сохранения адреса при отказе геокодера. Голосовые уведомления проверяются с декодированием и воспроизведением настоящих аудиофайлов, выключением звука и защитой от повторного воспроизведения.

`npm run typecheck`, `npm run lint` и `npm run build:web` завершились успешно.

## Стенд и ограничения

- Отдельный локальный экземпляр MariaDB 10.4.24: `127.0.0.1:13316`, база `taxi_qa_20260909`, применены 45 миграций. API: `127.0.0.1:4110`. Исходная база проекта не использовалась для тестовых заказов.
- Клиент проверялся в Microsoft Edge/Chromium, преимущественно 390 × 844. Для пяти сессий использовалась собранная версия на `localhost:8090`; адрес API и сокета перенаправлялся на тестовый сервер в контексте браузера. Ответы API и события поездок в этом прогоне не подменялись.
- Для проверки интерфейса сессии тестовых аккаунтов создавались заранее. Полный вход через реальные VK, MAX, Telegram и доставку SMS этот прогон не проверяет: интеграции проверены автоматическими тестами с контролируемыми ответами провайдеров.
- Тестовые аккаунты и заказы очищаются после интеграционных и браузерных сценариев. Внешние уведомления отключены на стенде; реальные пассажиры и водители не получали тестовые заказы.
- Не проверялись физические Android/iOS-устройства, фоновая геолокация на реальном телефоне, доставка push через магазины/ОС, боевой MySQL 8 и поведение при продолжительной производственной нагрузке. Результаты не означают доказанную проверку всех возможных комбинаций условий.
- Исправления находятся в рабочем проекте; публикация на боевой сервер в эту проверку не входит.
- После проверки отдельные QA API и база остановлены. Данные стенда сохранены в игнорируемом каталоге `tmp/qa-20260909/mysql`; тестовых заказов и аккаунтов `QA` в нём не осталось. Демо Metro на `localhost:8082` и просмотр собранной версии на `localhost:8090` оставлены запущенными.

При запущенных изолированных базе и API каждый интеграционный набор запускается отдельно:

```powershell
node docs/design/run-qa.mjs node_modules/vitest/vitest.mjs run tests/api.integration.test.ts
node docs/design/run-qa.mjs node_modules/vitest/vitest.mjs run tests/concurrent-orders.integration.test.ts
```

Не запускайте эти два набора одновременно против одной базы: исходные тесты изменяют общие настройки тарифов и диспетчеризации. Браузерный тест также запускается отдельно от интеграционных наборов:

```powershell
$env:TAXI_PLAYWRIGHT_PATH = '<путь к установленному playwright>'
node docs/design/run-qa.mjs node_modules/tsx/dist/cli.mjs docs/design/verify-concurrent-orders.cjs
```

`run-qa.mjs` удаляет из окружения ключи внешних провайдеров и задаёт локальные адреса, тестовую базу и режим SMS в консоль. Тест конкурентных заказов дополнительно запрещает базу с неподходящим именем и нелокальный адрес API.
