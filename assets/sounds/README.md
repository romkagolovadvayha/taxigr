# Голосовые уведомления

29 русских записей нейросетевым мужским голосом `ru-RU-DmitryNeural`, естественный темп и высота (`+0%`, `+0Hz`). Это синтетический голос, а не запись человека. Тексты и настройки находятся в `voice-manifest.json`. Синтезируются только фиксированные фразы без имён, телефонов, адресов или текста чата.

Озвучиваются поиск, назначение водителя (в том числе занятого предыдущей поездкой), его освобождение, выезд, прибытие, начало и завершение поездки, обе формы оплаты и просьба поставить оценку. Водителю адресована просьба оценить пассажира. Для старого варианта оплаты `direct` способ расчёта не придумывается.

Отдельные записи сообщают об отказе водителя и поиске другого, отмене пассажиром или администратором, истечении времени поиска, принятии текущего/следующего заказа и переходе к следующему. Есть фразы о повышении цены, входящем сообщении и пример голоса.

Продолжительность 1,2–8,7 секунды; для системных push — mono PCM WAV, 44,1 kHz, 16 bit, пиковый уровень −3,5 dBFS. Короткие паузы и плавные границы защищают согласные от обрезания и убирают щелчки. Для приложения используются компактные MP3 (mono, 24 kHz, 64 kbit/s), каждый меньше 100 КБ.

Исходные MP3 сохранены в `voice-source`. Воспроизведение использует готовые записи: синтезатор, ключ API и онлайн-генерация речи на устройстве не нужны. WebAudio получает разрешение на звук после взаимодействия с сайтом; загруженные фразы кешируются в памяти на время сеанса.

События разных заказов и чата произносятся по очереди. Новый статус того же заказа заменяет устаревшую фразу: отмена не ждёт окончания «водитель найден». Очередь ограничена, старые сообщения не воспроизводятся спустя долгое время. Выключение звука, выход из аккаунта и уход в фон останавливают речь и очищают очередь.

Изменения заказа обрабатываются до объединения обновлений React. Завершение текущей поездки не теряется при одновременном переходе к следующей; отмена следующего заказа озвучивается до удаления карточки. Восстановление сессии, координаты и дубли событий не повторяют известные статусы. Новый цикл поиска и назначения озвучивается снова.

## Обновление записей

1. Изменить `voice-manifest.json`.
2. С установленным пакетом Python `edge-tts` выполнить `python scripts/record-notification-voice.py` (нужна сеть). Перезаписываются изменённые фразы; при замене голоса — все.
3. Выполнить `npm run sounds:generate` (FFmpeg; обработка локальных исходников без сети).

Генератор проверяет соответствие исходных записей текстовому манифесту. Для правки только громкости или формата достаточно третьего шага. `voice-metadata.json` содержит тексты, длительности и размеры готовых файлов.

## Платформы

В открытом приложении громкость речи управляется настройкой «Голосовые уведомления» и системной громкостью устройства. В Android/iOS фоновые push используют встроенные звуки и системные настройки уведомлений. Новые звуки фоновых push требуют новой нативной сборки; обновления только JavaScript недостаточно. При миграции новых Android-каналов наследуется отключённый звук, важность и вибрация прежних каналов. В закрытой веб-странице браузер воспроизводит системный звук push, а не произвольную голосовую запись.

Старые каналы основных статусов оставлены с прежними именами ресурсов, чтобы их настройки сохранились. Для чата, выезда водителя, повышения цены и общих уведомлений добавлены отдельные каналы с подходящими фразами. Сервер и новая нативная сборка должны публиковаться согласованно; на старых сборках новые файлы отсутствуют.
